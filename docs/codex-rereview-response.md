# 再査読への対応

2026-09-10。`bafb87f` に対する [Claudeの再査読](claude-rereview.md) を受領。査読文書は変更せず保存した。

## オフライン未保存の案内

修正前の製品版に `toBeInViewport({ ratio: 1 })` を追加すると、viewport ratio 0で失敗することを確認した。従来の `toBeVisible()` では見逃していた欠陥である。

- 案内を画面上部に固定し、実際の高さを計測してアプリの余白・盤の幅・画面高を調整。スクロールしても案内を読め、通常の対局では盤や操作を覆わない。
- 幅変更や文字拡大時もResizeObserverで追従。保存成功時には案内と余白を取り除く。
- 前回のCSS追加で `html,` と `body` のセレクターを分断し、htmlにも案内用の余白・最大幅がかかっていたため、併せて正しい組に戻した。
- 製品PWAの保存障害3種 × 配信ヘッダーあり／なし × 390×844／360×640で確認。案内・盤・4つの操作ボタンが視界に収まること、案内と盤が重ならないこと、初期スクロール位置0、保存復旧後の余白0を検査する。表示中に幅と案内の文字サイズを変える場合も確認。

## #9: 深さを信頼度として見せない

提案1の「形勢を言葉で示す」を採用した。カットインと振り返りで「形勢の目安」を見出しにし、「互角」「先手よし」「後手優勢」などの言葉で比べる。緑の手も「正解」から「候補の手」へ改めた。

画面から1点単位の評価値、換算勝率、「読みN手」を取り除き、深さ14で留保の有無を分ける処理を廃止。深さが大きいと確実な数字に見える区別をなくした。数値を丸めて内部判定を変えることはせず、評価値・探索の深さ・PVは記録や回帰試験に残している。5段階の台詞、一手一台詞、判定の閾値、固定素材・効果音は維持。

再査読の17手読み50→75、13手読み253→252を表示の回帰試験へ反映した。それぞれ「互角」「先手よし」という同じ表現になり、生の評価値は記録に残る。深さ3・12・13・14・17・20でも同じ表示方針になることを検証。

長めに読み直して候補の一致を調べる提案2は、今回の表示変更には追加していない。同じ候補が返っても正しさの保証にはならず、応答時間も変わるため別途の検証が必要。今回の改善を「推奨手の安定性が検証済み」とは説明しない。

## 試験中に見つけた画面と履歴の競合

一括操作試験で、WebKitの「設定から戻ってすぐ開き直す」経路が1回失敗した（39/40）。対象だけの10回は通過したが、履歴の移動完了より先に設定画面を表示できる経路を確認した。古い設定の段数も新しい設定の段数も1なので、画面と `history.state.ojiji` が一致しているだけでは移動の完了を確認できていなかった。

次の設定・対局は履歴の整合が済んでから表示し、待機中に選び直した場合は最後の画面要求だけを反映するよう修正。履歴移動を250ms遅らせる試験で、修正前は次画面を先に表示して失敗し、修正後は履歴と表示が揃ってから進むことを確認した。

この修正で、以前から記録しているWindows版WebKitの異常終了原因まで解明したとはしていない。
