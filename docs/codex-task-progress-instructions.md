# Codex 向け作業指示書: 課題の達成状況を見えるようにする

作成: 2026-09-14 / 作成者: Claude（査読担当）
起点: `d74cf72`

## 背景

ユーザーがブラウザで遊び、こう言った。

> 課題の達成に関してですが、全体としてどれだけの課題があり、現在までにどれだけ達成しているかが分かりにくい

調べたところ、**分かりにくいのではなく、見えていない。** 原因は 3 つあり、うち 1 つは欠陥である。

この指示書で直すのは **1 と 2 だけ**。3 は範囲外（後述）。

## 確認した事実

### 課題は全部で 39 個ある

課題は `戦法:課題id` で記録される（`doneTaskSet`）。共通課題 5 つは**戦法ごとに別勘定**なので、合計は次のとおり。

| 戦法 | 固有 | 共通 | 計 |
|---|---|---|---|
| 矢倉 | 3 | 5 | 8 |
| 四間飛車 | 3 | 5 | 8 |
| 角換わり | 3 | 5 | 8 |
| **棒銀** | **2** | 5 | **7** |
| 中飛車 | 3 | 5 | 8 |
| | | | **39** |

**棒銀だけ 7 である。** ここが後の試験で効く。

### 原因 1: 叱られると課題の達成数が画面から消える【欠陥】

`src/ui/settings.ts:70-72`。

```ts
const taskCount = [...done].filter((k) => k.startsWith(style.id + ':')).length;
const recText = rec && rec.games > 0
  ? `<em>${rec.wins}勝 ${rec.games}局</em>${rec.scolded > 0 ? `<em>ばかもん ${rec.scolded}回</em>` : `<em>課題 ${taskCount}</em>`}`
  : '<em>未対局</em>';
```

**三項演算子なので、ばかもんと課題は同時に出ない。** 一度でも「ばかもーん！」を言われた戦法では、課題の達成数が消える。

実際の保存データで再現した（390×844）。

```
矢倉      3勝 5局 | ばかもん 2回 | 初勝利    ← tasksDone は 3 件あるのに見えない
四間飛車  1勝 3局 | 課題 1
```

**向きが逆である。** 叱られた戦法ほど繰り返し遊ぶので、その戦法でだけ進捗が見えなくなる。初心者が最も励ましを要る場面で消える。

### 原因 2: 分母が無い

「課題 1」が 8 個中の 1 個なのか分からない。未対局の戦法には課題の数がまったく出ないので、**その戦法に何個あるのかを知る方法が無い**。

### 原因 3: 合計は計算されているのに表示されていない【範囲外】

`src/ui/title.ts:58` が `totals(progress)` を呼び、`totals()` は `tasks` を計算する。しかしタイトルが描くのは勝数・局数・皆伝だけで `tasks` はどこにも出ない。`src` 全体で `.tasks` を読む箇所は無い（代入する `progress.ts:347` のみ）。

**これは今回触らない。** 理由は「範囲外」の節に書く。

### なぜ原因 1 が残ったか

**`joseki-btn` の成績表示を見ている試験が 1 件も無い。** `tests/e2e/screens.spec.ts:28-32` は「次の課題」と「皆伝」を見ているが、戦法一覧の行の中身は見ていない。開発時 Service Worker の件（`src/sw.test.ts` が開発分岐を通っていなかった）と同じ形である。

## 作業

### 1. 先に再現する

これまでと同じく、直す前に失敗する試験を作る。

- 保存データに「`scolded > 0` かつ `tasksDone` が 1 件以上ある戦法」を用意し、戦法一覧の行に課題の達成数が**出ないこと**を確かめる試験を書く。
- この試験が修正前に落ち、修正後に通ることを報告する。

### 2. 欠陥を直す — 課題とばかもんを両方出す

三項演算子をやめ、**課題は常に出す**。ばかもんは 0 回より多いときだけ添える（現状どおり）。

### 3. 分母を付ける

`tasksFor(style).length` を分母にする。**数を直接書かないこと。** 棒銀は 7 なので、8 を定数で書くと壊れる。

`tasksFor` は `src/game/progress.ts` から export 済みだが、`src/ui/settings.ts` はまだ import していない。追加すること。

### 4. 表示の形 — 行の高さを増やさないこと

**ここが実装上いちばん注意の要る点である。**

`src/style.css:918` に `.joseki-btn em { display: block; }` がある。**`<em>` は 1 つで 1 行**になる。素直に `<em>` を足すと戦法 1 行あたり 11px × 1.35 ≒ 15px 増え、5 戦法で **約 75px** 増える。

対局設定は 360×640 で既に 664px（24px スクロール）である。75px 足すと 100px のスクロールになり、**前回「ごちゃごちゃ」を直したばかりの画面が元に戻る。**

**課題とばかもんを同じ `<em>` に入れ、1 行に収めること。** 未対局の行も 1 行のままにする。

| 状態 | 表示（`.jr` の中） | 行数 |
|---|---|---|
| 未対局 | `未対局・課題 0/8` | 1（現状 1） |
| 対局あり・叱られていない | `3勝 5局` ／ `課題 3/8` | 2（現状 2） |
| 対局あり・叱られた | `3勝 5局` ／ `課題 3/8・ばかもん 2回` | 2（現状 2） |

**高さは 1px も増えない。** 区切り文字や語順は任せるが、**行数を増やす形は採らないこと。**

`.joseki-btn em` には `white-space: nowrap` があるので折り返さない。360px 幅で `.jd`（戦法の説明）が省略記号で潰れすぎないことを実測で確かめること。潰れるなら区切りを詰めるか、`.jd` 側の扱いを調整する。**`em` を折り返し可にして行数を増やす解決は採らないこと。**

### 5. 達成数が分母を超えないようにする

`normalizeRecord`（`src/game/progress.ts:198`）は `tasksDone` を文字列として受け取るだけで、**課題 id が今のコードに存在するかを検証していない**。将来 `STYLE_TASKS` から課題を 1 つ消すと、古い保存データが残って `8/7` のような表示になりうる。

達成数が分母を超えない形にすること。**方法は任せる**（表示時に丸める、読み込み時に未知の id を捨てる、など）。選んだ理由を報告すること。

**注意**: 読み込み時に捨てる方式を採ると、保存データが不可逆に変わる。採るなら、その影響（別の版へ戻したときに達成が失われる）を報告に書くこと。

### 6. 試験を足す

原因 1 が残ったのは試験が無かったからなので、ここは必ず埋める。最低限これを入れる。

1. `scolded > 0` かつ `tasksDone` が 1 件以上の戦法で、**課題の達成数とばかもんの回数が両方出る**。
2. `scolded === 0` の戦法で、課題の達成数が出てばかもんは出ない。
3. 未対局の戦法で、`課題 0/<その戦法の課題数>` が出る。
4. **棒銀の分母が 7 で、他の 4 戦法が 8 である。** 定数を書いたら落ちるように、`tasksFor` から期待値を作らず**数字を直接書いた試験**にすること。
5. 達成数が分母を超えない（壊れた保存データを渡しても `8/7` のような表示にならない）。
6. 360×640 で、戦法一覧の高さが修正前と**変わらない**こと。実測値を報告に書く。

1〜5 は単体・操作試験のどちらでもよい。`tests/e2e/screens.spec.ts` に足すか、`src/ui/` に新しい試験ファイルを作るかは任せる。**選んだ場所と理由を報告すること。**

## 範囲外（やらないこと）

次の 3 つは**今回やらない**。手を出したら差し戻す。

- **原因 3 の `totals().tasks`。** タイトル画面に合計を出すかどうかは、課題一覧を別ページに出す案（ユーザーが保留中）とまとめて決める。いま単独で出すと、後で置き場所を変え直すことになる。死んだ値を消すのも待つこと。
- **課題の一覧と達成状況を見る画面。** 保留中の案に含まれる。`ScreenName` と `src/ui/navigation.ts` には触れない。
- **「昇級まで: あと 2 勝・課題 3」の物差しの違い。** 勝は今の強さでの数、課題は全戦法・全強さの通算である。必要数が段位で 3→6 と増えて計算は合っているので、今回は直さない。

**合計 39 という数字を画面に出さないこと。** 39 のうち 25 は同じ共通課題 5 つの繰り返しなので、「3/39」と出すと、矢倉で学べることを全部終えた人にも 8% と表示される。遊ぶ側の単位は戦法ごとである。

## 変えてはいけないもの

- オジジの 5 段階の台詞、一手につき台詞は一つ。
- 音は駒音と雷だけ。雷の音量 10%。オジジに声は付けない。
- タイトルは全身、対局は顔のみ。
- 固定素材（`public/raizo/`、`public/sfx/`、`public/engine/`）とクレジット表記。
- 「（公開先 URL）」に仮の値を入れない。`npm run release:check` が 4 か所で失敗するのは意図どおり。
- `pickTask` の選び方（対局数を種にする決定的な順送り）。設定画面で見せた課題がそのまま対局に出る性質を壊さないこと。
- 課題の文言そのもの。
- 免状の札（初勝利・叱られず勝利・皆伝）の表示。
- 試験を `continue-on-error` や条件分岐で黙らせないこと。
