## ワークフローと設定の変更を点検した

`0062b12..0171242` の差分を読み、**検査を弱める変更は 1 件も無い**ことを確認した。

強くなった点だけがある。

- artifact の条件が `failure()` 限定から `always()` になり、成功時もレポートが残る。保存対象が HTML だけから `logs/e2e` / `logs/pwa` 全体に広がった。
- `if-no-files-found: error` が全 artifact に付き、証拠が生成されていない場合に警告ではなく失敗になる。
- 3 つの Playwright 設定に JSON レポートが追加され、件数・再試行・skipped を機械的に検査できるようになった（**今回の私の照合はこれに依拠している**）。
- 操作試験の trace が `on-first-retry` から `retain-on-failure` に、動画も `retain-on-failure` になった。
- ジョブのトークン権限が `contents: read` に限定された。

**変わっていないもの**（報告どおり）: 試験件数、`retries`、対局手数、`judgeMs`、各タイムアウト。`fullgame` のステップ上限 25 分は今回より前の差分で、実測 55 秒〜1 分 11 秒なので追加の延長は不要だったという説明も妥当である。

## 所見（欠陥ではない）

- **`origin/main` の先端（`0679c1f`）の CI 結果が記録に無い。** 3 回の run は `0171242` に対するもので、その後に報告書の追記（`docs/ci-bringup.md` のみ、90 行追加）をコミットして push している。push で 4 回目の run が起動しているはずだが、記録に含まれていない。文書だけの変更なので通る見込みが高いものの、**「通った」ことは確認されていない**。次に GitHub を触るときに結果を確かめて追記すれば足りる。
- **操作試験に `retries: 1` が残っている。** 今回は 3 回とも実際に再試行ゼロで通ったので証拠としては傷が無い。ただし、ゲートとして「不安定さを捕まえる」目的なら、1 回で落ちたものが `flaky` として緑になる余地は残る。CI では `retries: 0` にして、落ちたら落ちたと出す方が、この先の判断材料になる。今回の評価には影響させない。
- **Actions v4 の Node 20 非推奨警告**は報告どおり残っている。警告を隠していないのは正しい対応。保守課題として `actions/checkout` と `actions/setup-node` の更新を将来行えばよい。
- **「決め手」は 3 回とも 0 件。** 実対局で表示されるところは依然として未確認。これは指導・ゲーム側の残条件で、CI の成否とは別。
- **`src/main.ts` は 1,068 行、`src/style.css` は 1,629 行。** 画面ごとの切り出しは `src/ui/` に 7 モジュール進んだが、対局の制御は main に残っている。直近の査読で品質保証の残条件には挙げていないので今回の評価には反映しないが、人が増えるときに最初に問題になる箇所である。
- 作業 0 の記録（`.git` の拒否 ACL、GitHub CLI の資格情報が別アカウントで使えない件）は、**ACL を削除せず、トークンを平文に書き出さず、サンドボックスを弱めずに解決している**。判断として適切で、同じ制約が再発したときの対処も書かれている。

## 品質保証を 8 とする理由

直近の査読で、この領域の残条件として挙げていたのは次の 2 つだった。どちらも解消した。

1. **GitHub 上で CI が一度も走っていない。** → 同一コミットで連続 3 回成功。21 ステップすべてが実行され、素通りは無い。成果物を取得して中身まで照合した。
2. **WebKit の異常終了が未解明。** → Linux で 66 件が再試行なしに通り、Windows 固有として切り分けられた。3 回の非再現で全環境を断定しない、という留保の付け方も正確である。

加えて、この立ち上げで**証拠の残し方自体が改善された**。成功時もレポートが残り、JSON で件数・再試行・skipped を機械的に検査でき、証拠が無ければ失敗する。今回私が報告を照合できたのはこの変更のおかげで、**次の査読も同じ方法で検証できる**。ゲートとして機能する形になった。

8 は「リリースして恥ずかしくない」水準を指し、満点ではない。残るのは上の所見のうち `retries: 1` と main.ts の大きさで、いずれも今すぐ止めるべき問題ではない。
