## 変更の内容

`public/coi-serviceworker.js` の 3 か所が、指示どおりに直っている。

| 場所 | 変更 |
|---|---|
| `install` | 開発時は `skipWaiting()` を呼び、待機せず新しい Worker へ進む |
| `activate` | 開発時は `clients.claim()` の後に自スコープの開発用キャッシュを削除して戻る |
| `fetch` | 開発時は `return withIsolation(await fetch(req))` の一行。キャッシュの読み書きも代替取得もしない |

製品側の分岐は、`VERSION !== 'development'` の判定が不要になったぶんが簡素化されただけで、挙動は変わっていない。

`clients.claim()` を先に、キャッシュ削除を後に置く順序も正しい。古い Worker に取得させたまま土台を消さない。

`.claude/launch.json` の起動（現在は 5173）でブラウザを開き、実際に遊んで確かめた。

```

```

### 開発分岐の試験（以前はゼロ）

`src/sw.test.ts` の `worker()` に `development` の選択肢が付き、**`VERSION` を差し替えずに読み込む経路**ができた。これが無かったために今回の欠陥が生き残っていたので、根の部分が塞がれている。

追加された検査は次のとおりで、いずれも要点を突いている。

- 登録から通信・再試行まで**一度もキャッシュを開かない**（`cacheCalls` が空、`stores` も空）。同じ URL を 2 回取りに行き、更新後の内容が返る。COOP/COEP は付く。
- 通信失敗時に、保存済みの `old main.ts` があっても**返さずエラーになる**。
- 開発時の `activate` が自スコープの開発用キャッシュだけを消し、**製品のキャッシュ・META・別スコープの開発用キャッシュ・他アプリの保存は残す**。
- ナビゲーションの通信失敗を隠さず、404 もそのまま返す（ヘッダー付き）。
- **製品の初回・更新では `skipWaiting` を呼ばない**。私が「変えてはいけない」と書いた製品側の方針が、試験として固定された。

最後の 1 件は指示書に無かったもので、良い追加である。

### ポートの統一

`vite.config.ts` の `server` に `port: 5173, strictPort: true` が入り、`.claude/launch.json` は `npm run dev` をそのまま呼ぶ形になった。**どの起動方法でも 5173 になる。** 実際、私が起動設定から立ち上げたサーバーも 5173 だった。Playwright の 5179 / 5180 / 5181 / 5182 とは衝突しない。`strictPort` なので、埋まっていれば黙って別ポートへ移らず失敗する。README にも書かれている。
