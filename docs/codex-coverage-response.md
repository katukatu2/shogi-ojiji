## 指摘1: 不明な戦法が矢倉へ読み替わる

`--style` に不明なID・値の欠落・次の引数を渡した場合は、使用できるIDを表示して終了コード1を返す。エンジンの起動と出力ファイルの作成・上書きより前に検査する。

不明なIDと末尾の値の欠落について、修正前に終了コード0となって落ちる回帰試験を先に確認した。修正後は既存ログを維持することも確認。実CLIに `--style does-not-exist` を渡した実行も終了コード1で、指定した出力ファイルは作られなかった。

`--all-styles` を追加した。アプリが使う `STYLES` を直接順に処理するため、CIに別の戦法ID一覧を持たない。個別指定との併用は拒否する。各記録に戦法IDを加え、途中の例外があっても後続の局・戦法を試し、終了時は失敗を返す。全戦法2局ずつの処理と最初の局の例外を注入した試験でも、後続の記録とエンジン終了を確認した。

実エンジンで全5戦法×2局を実行し、10局・584手の記録を得た。エラー0件、戦法IDのない行0件、全IDが各2局ずつ存在する。棒銀2局は52手で終了し、他8局は60手の採取上限。ログの `draw` をルール上の引き分けの証拠とは扱わない。今回の採取は既定の判定80ms・Nodeの1スレッドであり、前回の400ms採取とは条件が異なる。

## 所見への対応: 製品通し試験をCIへ登録

```bash
npm run build
npm run e2e:fullgame
npm run selfplay -- --all-styles --games 2 --plies 60 --out logs/ci-all-styles.jsonl
```

通し操作を `scripts/product-game.ts` に切り出し、従来の手動CLIと新しいPlaywright試験から共通で呼ぶ。新しいコマンドは製品配信サーバーを起動・終了し、独立したブラウザ保存領域で盤・持ち駒・成り選択・カットイン・結果を操作する。開発APIがないこと、実盤の詰み、結果画面と1局分の保存を検査する。局面・棋譜・進捗は注入しない。

1局15分、全体20分、再試行0回。CIの必須ステップに登録し、成功・失敗いずれも棋譜・画像・レポートを保存する。失敗時にはトレースも残す。`npm test` は単体試験として維持し、この長い試験は別コマンドで実行する。

最初の組み込み確認は65手で詰み・保存の検査を通ったが、Windowsの子プロセス停止処理で配信サーバーの終了待ちが続いた。自分が起動したサーバーを停止するとCLIは終了した。同じHTTPハンドラーを返す `createStaticServer` を用意し、Playwrightのセットアップから直接管理するよう変更。最終実行は63手で詰み・先手勝利・1局1勝を保存し、**手動停止なし、48.2秒、終了コード0**で終了した。

今回の63手では角の捕獲・被捕獲があり、保存には角交換課題が付いた。未交換時の否定分岐はこの1局では通っていない。前回57手の未交換対局の証跡と単体の誤課題回帰試験は維持している。「決め手」は今回も0件で、実例確認は未完了。
