# 将棋オジジの定石指南

オジジは毎回、得意戦法（まずは矢倉）で囲ってくる。プレイヤーは自由に指してよい。
ただし、その戦法相手にやってはいけない手を指すと、オジジがカットインして「ばかもーん！」と叱り、正しい手を教えてくれる。
企画は [docs/plan.md](docs/plan.md)。

開発引き継ぎ後の現在地は [リリース査読記録](docs/release-audit.md)。iPhone App Store・Android・Web を今回の対象とする。公開先・連絡先と実機検証が未完了で、まだ公開可能とは判定していない。

## 開発

```bash
npm ci
npm run dev        # http://localhost:5173
npm test           # エンジンと定跡のテスト
npm run typecheck
npm run build      # dist/ に静的ファイルを出力
```

## テスト

```bash
npm test                          # vitest（ルール・エンジン・定跡・振り返りなどの単体テスト。src/**/*.test.ts）
npm run e2e                       # Playwright の E2E（tests/e2e/*.spec.ts。vite dev を 5179 番で自動起動する）
npx playwright install chromium webkit   # E2E の初回だけ。Chromium が無ければ入れる
npx playwright show-report logs/e2e/report   # 直前の E2E のレポートを開く
```

- E2E は `playwright.config.ts`。Chromium と WebKit、スマートフォン相当の画面（375×667）、失敗時は 1 回だけ再試行し、そのときトレースを残す。結果とレポートは `logs/e2e/`（git 管理外）。
- 確かめる流れ: タイトル → 対局設定 → 対局（「対局開始」の演出）、駒をタップして▲７六歩を指しオジジが応手する、形だけの NG（▲４八玉の玉飛接近）でカットインが出て「指し直す」で戻る、ヒント・待った、投了 → 結果 → 「同じ設定でもう一局」、設定の保存（再読み込み後のタイトルに前回の戦法・強さ）、初回の動線（`localStorage` が空なら対局設定を必ず通る）。
- エンジンの有無に依存しない。やねうら王が動かない環境では「判定: 簡易」のまま進み、ヒントは「出せん」と言うだけで、どちらでも通る。`OJIJI_E2E_NO_ENGINE=1 npm run e2e` でエンジンのスクリプトを読ませず、その環境を再現できる。
- セレクタは画面の文言（`getByRole` / `getByText`）が中心。クラス名は盤のマス（`.board .cell`、9×9 を行優先）と最終手・吹き出し・カットインの容器だけ。開発サーバーでは `window.__ojiji.game()` で手数などの状態を読む。
- `tests/e2e/` は vitest の対象から外してある（`vite.config.ts` の `test.exclude`）。
- CI（`.github/workflows/ci.yml`）でも Chromium・WebKit を入れて `npm run e2e` を回し、失敗時はレポートを `playwright-report` として保存する。

## 収録している戦法（オジジが指す側）

| 戦法 | オジジの組み方 | 対局後の教え（例） |
|---|---|---|
| 矢倉 | 標準型・飛車先速攻型・早囲い型 | 角交換を狙え、端が泣き所、囲ってから攻める |
| 四間飛車 | 美濃囲い型・藤井システム風・振り飛車穴熊型 | 急戦か持久戦か決めよ、美濃は上と端から |
| 角換わり | 腰掛け銀型・早繰り銀型・棒銀型（一手損角換わり。相手が角道を開けたら△８八角成） | 打ち込みを消す▲７八金、三大戦法から選べ |
| 棒銀 | 本格型・速攻型 | 銀の頭を叩け、８七を守る銀か角を用意 |
| 中飛車 | ゴキゲン標準型・早囲い型 | ５筋を金銀で守れ、５五の歩が生命線 |

戦法ごとに、駒組みの節目の独り言、良い手の形（頷き）、NG の形、対局後の一言を持つ（`src/style/*.ts`）。
共通の受け（▲２五歩には△３三角、端歩は受ける、など）は `src/style/common.ts`。

## 画面と動線

- タイトル → 対局設定 → 対局 → 結果。タイトルは全身のオジジと題名とボタンだけで、強さと戦法は「対局設定」で選ぶ。
- 2 回目以降のタイトルには「前回の設定で始める」（前回の戦法・今の強さ）が出て、1 タップで対局に入れる。前回の戦法は `ojiji.progress.v2` の `lastStyle` に保存する。
- 対局設定は前回の戦法が選択済みで開き、選んだ戦法の囲いの形（`src/game/formation.ts`。オジジの駒組みだけを盤に並べる）・成績・次の課題を見せる。
- 結果画面は「同じ設定でもう一局」が主ボタン。「戦法を変える」で対局設定へ戻る。「今日の 3 手」はカードをタップすると拡大表示（大きな盤で「指す前」「指した後」を切り替え、正解の手を緑で示し、形勢の変化と説明を出す。前後の手にも移れる）。
- 戻る操作は履歴の深さ（タイトル 0・設定 1・対局 2）で管理し、popstate で受ける。設定→タイトル、対局中→確認してからタイトル、結果→タイトル。Capacitor の Android は WebView が戻れる間は戻る操作を WebView に渡すので同じ動きになる。

## 悪手判定の仕組み（5 段階）

指した手を将棋エンジン（やねうら王 K-P、水匠 Petite 内蔵）で評価し、「どれだけ落ちたか」と「落ちた結果どうなったか」で反応を決める。

| 段階 | 反応 | 条件（先手視点の点数） | 手を止めるか |
|---|---|---|---|
| 1 | 無言で頷く | 評価の落ち幅が反応の条件に当たらない。良い形（角交換・端攻めなど）なら一言添える | 止めない |
| 2 | 良い手じゃな。だがワシならこう打つな。 | 150 点以上落ちたが、指したあとも +150 以上で、段階3以上の条件に当たらない | 止めない。吹き出しとオジジの手の緑表示 |
| 3 | むう… | 300 点以上落ちたが、まだ -150 以上（互角以上）。指したあと +500 以上でも 300 点以上落ちればここ | 止めない。吹き出し |
| 4 | それは悪手じゃろう | 300 点以上落ちて -150 未満に転落、または 700 点以上落ちた。形だけの NG（囲わず攻める、玉飛接近など）もここ | 静かなカットイン（声なし）。指し直し可 |
| 5 | ばかもーん！ | 1200 点以上落ちた、5 手以内の詰みを許した、3 手以内の詰みを見逃した。長い詰みは落ち幅で判断する | カットイン＋雷（声なし）。指し直し可 |

- カットインでは「形勢の目安」の下に「候補 ▲○○ → 互角」「指した ▲△△ → 後手優勢」のように言葉で比べる。緑の手の表示は「候補の手」とし、探索時点の提案であることを明示する。吹き出しには説明の台詞だけを出す。
- 説明文は「指すべきだった手が何をする手だったか」（駒が取れた、王手が厳しかった、取られそうな駒を守れた）を先に言い、相手の応手は「取られる・王手される・成り込まれる」のときだけ添える。取られる駒は名前で言い（「△７五銀と飛車を取られる」）、同等以上の駒を取った後の取り返しは「角銀交換になる」と言う。同じ駒の話を二度は言わない。
- 深さだけでは評価や候補の安定性を保証できないため、`SHALLOW_DEPTH`による表示の区分は廃止した。画面には1点単位の評価値・換算勝率・「読みN手」を出さず、振り返りも同じ「形勢の目安」で示す。生の評価値と探索の深さは内部の判定・記録・検証に残す。閾値や悪手判定、候補の選び方は変更していない。
- しきい値は `src/style/judge.ts` の先頭の定数（`LEVEL2_DROP` など）で変えられる。
- エンジンが使えない環境（SharedArrayBuffer 不可）では、駒損と一手詰めだけの簡易判定に切り替わる。画面右上に「判定: 簡易」と出る。

- 最善手の狙いの説明（「ここは▲○○と…する手じゃ」）は、まず相手の狙いを読んでから言う。先手番の局面を後手番として（SFEN で手番を入れ替えて）読み、相手に手番を渡すと 150 点以上損する狙いがあり、最善手を指すとその狙いの手が非合法になるなら「△○○を防ぐ手」と言う（応手が変わっただけでは「防ぐ」と言わない）。狙いが無ければ盤の形から言い、「玉の守りを固める」は玉に接する駒に限る（離れた自陣の手は「自陣の隙を消す」）。

## 対局中の小言と対局後の一言

- 対局中はオジジがよく喋る。駒組みの節目（角道を止めた、矢倉完成、飛車先を伸ばした）に一言、王手や大駒を取られたときの反応、先手の駒に狙いをつけたときの小声の助言（6 手に一度まで）、エンジンの読みより良い手への「ほう」。
- ただし台詞は一手に一つ、かつ吹き出しが出ている間は新しい台詞を出さない（置き換えも順番待ちもしない）。プレイヤーの手への反応（頷き・段階 2〜3・カットイン）があった手では、続くオジジの独り言や小声は出さない。ヒント・待った・課題の表示は手の数に含めないが、吹き出しが出ていれば同じく出さない（`src/main.ts` の `showToast`）。
- 対局後は一言と一行の記録だけ。「ばかもん／悪手／ヒント／待った」の回数と、叱られ方に合わせた締めの一言（勝ちでヒントが多ければ「頼りすぎじゃ」など）。長い振り返りは出さない。

## 学習ループ（難易度・課題・振り返り）

- **難易度**: タイトルで「見習い／門下生／師範代」を選ぶ（`src/game/progress.ts` の `LEVELS`）。駒組みは同じだが、そのあとのオジジの手は「候補手の数・最善から何点以内をランダムに選ぶか・読みの深さ」が変わる。見習いは最善から 900 点以内・深さ 3 で、初心者でも勝てる。
- **今日の課題**: 対局ごとに一つ。戦法固有（角交換する、舟囲いを作る、銀の頭を叩く、など。頷く形の id と対応）と共通（囲う、ばかもんゼロ、ヒントなし、勝つ）から未達成のものを選ぶ。対局中は盤の上の一行に出し（オジジの台詞にはしない）、結果画面で達成を伝える。
- **昇級**: 今の難易度で 2 勝し、課題を累計で 3 つ（門下生では 6 つ）達成すると次の難易度へ。結果画面で知らせ、タイトルの選択も切り替わる。
- **今日の 3 手**: 結果画面に、形勢が最も動いたプレイヤーの手を最大 3 つ、小さな盤面つきで出す（`src/game/review.ts`）。動いた量は評価値の差ではなく勝率の差で測る（Lichess と同じ式で評価値を勝率に変換）。評価値は形勢が決まるほど膨らむので、点差で選ぶと負けが決まった後の手ばかりになるため。勝率 8 ポイント以上動いた手だけが候補で、足りなければ 3 手にこだわらない。悪化した手を優先し、同程度なら早い手（最初の間違い）を先にする。説明文は指す前と後の形勢（優勢・互角・劣勢・敗勢）で変える。長文の振り返りは出さない。
  - 勝った対局は「決め手」を 1 つ入れ、間違いは 15 ポイント以上のものを最大 2 つ、札は「ヒヤリとした手」。決め手は「最善と次善の評価差が大きい局面で最善を指した手」（判定機が MultiPV 2 で読んだ差 `gap` を記録に残す）。勝率が上がった手は決め手にしない（相手の間違いか読みの揺れであることが多い）。エンジンの最善と一致したと記録にある手（`playedBest`）だけを決め手にする。
  - 対局中に叱らなかった手は、あとで評価が下がっても「形勢を落とした手」に選ばない。最善を指した手（`playedBest`）とヒントの手（`hinted`）がこれで、ヒントの扱いは「ヒントの手を指した場合は、あとで評価が下がっても叱らない」と揃えてある。形勢を上げた手なら「好手」には出る。
  - 説明文の前置きは、対局中にオジジが何と言ったかで変える。段階 1（無言）で優勢から 15 ポイント以上落とした手は「勝っておったので黙っておったが、」、段階 2（「ワシならこう打つな」と言った手）が同じだけ落としていたら「ワシならこう打つと言ったが、実は大きな損じゃった。」を先頭に置いて形勢の文に続ける。段階 3 以上は対局中の説明をそのまま使う。
  - 同じ手数の記録が複数あるときは、後の（実際に指した）方だけを使う。指し直しや待ったで消えた手を蒸し返さないため。
- **称号と免状**: 戦法ごとに「初勝利」「叱られず勝利」「皆伝」（師範代でばかもん 0 かつ課題達成で勝つ）の免状が付く（`badgesOf`、`BADGE_LABEL`）。皆伝の数で称号が上がる（門前の小僧 → 通いの弟子 → 内弟子 → 免許皆伝、`titleOf`）。タイトルに称号と通算成績、対局設定の一覧に免状、結果画面に新しく付いた免状を出す。
- **引き分け**: 千日手・持将棋・400 手は引き分け（`GameResult` の `'draw'`）。局数にだけ数え、勝ちには数えない。連続王手の千日手は王手を続けた側の負け。
- 成績は `localStorage`（`ojiji.progress.v2`）。戦法ごとの対局数・勝ち数・課題達成・ばかもん回数・免状と、現在の難易度。

## ヒントと待った

- 「ヒント」ボタンで、オジジならどう指すか（エンジンの最善手）を盤面に緑で示す。理由は言わない。ヒントの手を指した場合は、あとで評価が下がっても叱らない。
- 「待った」ボタンで、自分の手とオジジの手を一組戻す。戻したオジジの手は「指し終えた扱い」になるので、次は別の駒組みの手を選びやすい。
- 使った回数はどちらも結果画面に出る。
- 指す前の形勢が -1000 より悪い（後手優勢以上）ときは、何を指しても言わない。

## オジジの指し手

1. 戦法の `plans` から対局ごとに組み方を一つ選ぶ（矢倉なら標準型・飛車先速攻型・早囲い型）。選んだ plan（優先順の駒組み。`'FU:8c8d'` のように駒種つき）を上から順に試す。合法で、エンジンが「最善より 80 点以内」と言えば指す。
   - その前に `reactions`（条件付きの受け）を見る。▲２五歩や２五・３五の銀で２四を狙われたら△３三角（無理なら△３三銀）、角道が通っていれば△４四歩、▲９六歩・▲１六歩には端歩を受ける、▲３五歩には３三に駒を用意する。条件が合えば駒組みより先に試す。
2. 王手されている、タダで取れる駒がある、50 手を超えた、plan が尽きた、のいずれかならエンジンに任せる。
3. エンジンは候補手 3 つのうち最善から 150 点以内の手をランダムに選ぶ（強すぎ防止）。

## エンジンについて

- [やねうら王](https://github.com/yaneurao/YaneuraOu) の WebAssembly 版 `@mizarjp/yaneuraou.k-p`（GPLv3）を使用。評価関数 SuishoPetite 内蔵で、合計約 2.6 MB。
- SharedArrayBuffer を使うため、配信時は次のヘッダーが必要。`vite dev` / `vite preview` は自動で付く。
  ```
  Cross-Origin-Opener-Policy: same-origin
  Cross-Origin-Embedder-Policy: require-corp
  ```
- ヘッダーを設定できない Web の静的配信では `public/coi-serviceworker.js` がヘッダーを補い、必要なら一度再読み込みする。本番はビルド全体を先に保存し、HTML・JS・素材を同じバージョンで使う。更新は既存タブを閉じた後に有効になる。`npm run build` がキャッシュの識別子と `dist/offline-assets.json` を自動生成する。ネイティブ WebView のエンジンは実機確認が必要。
- 初回のオフライン保存が失敗した場合、画面上部に案内を固定し、その高さだけ盤と画面の領域を調整する。案内が盤・操作ボタンを覆わず、通信復帰後に保存できたら案内と余白を消す。実ブラウザー試験は視界に入っていることも検査する。
- エンジンが使えない環境（SharedArrayBuffer 不可、読み込み失敗）では、その旨を一度だけ画面下に知らせ、簡易判定で続ける。

## オジジの絵（雷蔵パーツアニメーション）

- `public/raizo/`: 顔だけの Canvas 2D Web Component `<raizo-rig>`（`raizo-rig.js`）と `faces/` の顔 8 点（非可逆 WebP、幅 288px、合計約 135KB）。制作元の全身リグ（17 点・2.4MB）はスマートフォンの対局画面に常駐させるには大きすぎたので、顔だけに作り直した。`assets.js` は顔の URL を渡す薄い一覧。
- タイトル画面だけは全身を出す。体は `public/raizo/body.webp`（19KB の静止画。`python scripts/build-body.py` が制作元の体・袖・手を `assets-src/raizo/body/` から、元のリグと同じ位置・角度で合成する）で、その上に顔のリグを重ねる。位置の対応は `style.css` の `.title-screen .face.full raizo-rig`。
- 顔素材は `assets-src/raizo/heads/`（制作元の頭部）から `python scripts/build-faces.py` で作る。8 点を同じ倍率で縮め、`brow` は眉だけ切り出して `sour` に重ねる。
- 描画は動いている間だけ。単発動作の間と、ループ状態の中で動きのある区間（まばたき、首の傾げ、眉の上下）だけ `requestAnimationFrame` を回し、それ以外は 1 回描いて次の区間まで眠る。`prefers-reduced-motion` では表情だけ切り替える。
- 読み込み順は `index.html` で `assets.js` → `raizo-rig.js`。素材が読めない環境では `src/ui/ojiji.ts` の SVG にフォールバックする。
- `src/ui/rig.ts` が状態管理。要素は 1 つだけ作り、タイトル・対局画面の相手の行（52px の顔）・カットイン・結果画面の間で移動して使う。素材が読めなければ `onFail` で SVG の顔に切り替える。`play()` はゲームの出来事のときだけ呼び、単発動作の終了は `raizo-complete` で受け、再生番号で古い終了処理を捨てる。画面が隠れたら `pause()`。
- 状態の対応: idle（通常）／thinking（思考中・ヒント・待った・助言）／nod（良い手。台詞なし）／good（段階 2。湯飲みで一服）／doubtful（段階 3・王手）／bad（段階 4）／angry（段階 5）／surprised（プレイヤーの勝ち）。叱った後は解説中 thinking、閉じたら通常へ。
- 対局画面では盤の上の「舞台」にオジジと吹き出しを置き、盤・持ち駒・ボタンとは重ならない。
- 駒音は `public/sfx/koma.mp3`（約 15KB。「無料効果音で遊ぼう！（小森平）https://taira-komori.net/」の「将棋の駒パチン４」nc260487。容量が小さいので変換なしで使う）。プレイヤーとオジジの手を盤に反映するたびに鳴らす。
- 音声はオジジの声を使わず、「ばかもーん！」（段階 5）の場面だけ雷の効果音 `public/sfx/bakamon_thunder.mp3`（モノラル 96kbps、約 33KB）を鳴らす（`src/ui/audio.ts`）。元の WAV は `assets-src/sfx/` にあり、`node scripts/encode-sfx.mjs` で変換する（ffmpeg 不要、lamejs を使う）。1 本の `<audio>` で鳴らし、前の音を止めてから鳴らす。ミュートや再生失敗でも進行は止まらない。最初のタップで `<audio>` を解錠する。ファイルを差し替えたら `SFX_VERSION` を変える。

## 自動対局でオジジの台詞を点検する

```bash
npx vite-node scripts/selfplay.ts -- --style shikenbisha --games 25 --start 0 --seed 11 --out logs/run1.jsonl
npm run selfplay -- --all-styles --games 2 --plies 60 --out logs/ci-all-styles.jsonl
PYTHONIOENCODING=utf-8 python scripts/selfplay-report.py 'logs/run*.jsonl' > logs/report.txt
```

- 実機と同じ判定コードとエンジンを Node で動かし、戦型スクリプト（棒銀・四間飛車・中飛車・角換わり・居玉突撃など 12 種）＋弱めたエンジンでプレイヤー側を指す。
- 判定・独り言・頷きを 1 行 1 件の JSON で記録し、レポートで文型ごとの回数、疑わしい判定（正解の形勢が指した手以下、段階 2 なのに互角以下など）、段階ごとのサンプルを出す。
- `--style` の不明なID・値の欠落は、エンジンを起動せず既存ログも上書きせずに終了コード1を返す。`--all-styles` はアプリの `STYLES` 一覧を直接使い、登録された全戦法を順に処理する。個別指定との併用はできない。
- 4 プロセス並列で 100 局が 10 分弱。`logs/` は git 管理外。CI（`.github/workflows/ci.yml`）は全戦法を各2局・60手まで試す設定。例外が起きても後続を試し、1件でも失敗すれば終了コード1を返す。ログには戦法IDも残る。CI自体はまだ未実行。

## 戦法を追加する

1. `src/style/` に新しいファイルを作り、`Style` 型のデータを書く（`shikenbisha.ts` が手本）。
   - `plans`: オジジの駒組みを何種類か。各 plan は優先順に「駒種:USI」で書く（例 `'FU:8c8d'`、`'OU:5a4a'`）。
   - `reactions`: 共通の受け `COMMON_REACTIONS` をそのまま使うか、必要なものだけ選ぶ。戦法の看板になる手（角換わりの△８八角成など）は、その受けだけ `tolerance` を大きくして優先できる。
   - `planComments`: 節目の一言。キーは plan か reactions にある手。
   - `badPatterns` / `goodPatterns`: 共通の `COMMON_BAD` / `COMMON_GOOD` に、その戦法特有の形を足す。
   - `lessons`、`winLine`、`loseLine`。
2. `src/style/index.ts` の `STYLES` に登録する（タイトルに並ぶ）。
3. `npm test`。全戦法・全 plan について「相手が待っていれば駒組みが完成する」テストが自動で回る。
4. `npx vite-node scripts/selfplay.ts -- --style <id>` で自動対局し、台詞を点検する。
